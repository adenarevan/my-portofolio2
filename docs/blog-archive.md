# Arsip blog dan pendamping artikel

Blog publik memakai sembilan artikel per halaman. Tombol Sebelumnya/Berikutnya menggunakan cursor tanggal publikasi **dan ID dokumen**, sehingga artikel dengan timestamp yang sama tetap stabil. URL menyimpan kata kunci, topik dan batas halaman; refresh atau tombol kembali browser mempertahankan pencarian. Satu pembacaan mengambil paling banyak sepuluh dokumen, termasuk satu untuk memastikan apakah masih ada halaman berikutnya. Arsip tidak diunduh seluruhnya ke browser.

Pencarian memakai kata/prefix pada **judul dan topik**, bukan isi lengkap. Teks dinormalisasi ke huruf kecil dan aksen dihapus. Minimal dua karakter; maksimal enam kata pencarian, dicocokkan sebagai OR, diurutkan dari publikasi terbaru. Array `searchTokens` dibatasi 240 entri. Ini memakai query Firestore Standard yang sudah ada tanpa layanan pencarian berbayar. Rujukan: [query array dan batas](https://firebase.google.com/docs/firestore/query-data/queries), [cursor pagination](https://firebase.google.com/docs/firestore/query-data/query-cursors).

`portfolioBlogTopics/main` menyimpan daftar topik artikel terbit. Publik hanya dapat mengambil dokumen ini; penulisan dibatasi admin/worker dan timestamp server. Tidak ada isi, judul atau informasi draf di dalamnya. Penyimpanan/publikasi manual dan hasil bot memperbarui indeks yang sama. Publikasi sekaligus menambahkan topik melalui transaksi; penyimpanan draf tidak menambahkan topik publik. Semua query artikel publik tetap mewajibkan `status == published` dan limit maksimal 20 sesuai rules.

Tiga index tambahan mendukung status + topik, status + searchTokens, dan kombinasi keduanya, semuanya diurutkan menurut publishedAt descending. Indeks ditambahkan lewat API tanpa menghapus indeks aplikasi lain di project ADENA. Migrasi awal mengisi `searchTokens` pada enam dokumen yang sudah ada dengan precondition updateTime, lalu mengumpulkan lima topik terbit. Isi, tanggal artikel, status, metadata bot, akun dan pengaturan bot dipertahankan.

Di desktop lebar, halaman baca memakai tiga kolom: profil dan topik di kiri, sampul/isi di tengah, daftar isi dan tulisan terbaru di kanan. Pendamping menggunakan profil asli, topik nyata dan artikel terbit, tanpa angka popularitas atau iklan contoh. Ukuran menengah memakai dua kolom. HP memakai satu kolom dengan daftar isi yang bisa dibuka, profil/topik di bawah isi, serta rekomendasi di akhir. Daftar arsip pada HP memakai thumbnail ringkas. Kredit gambar yang sudah ada tetap tampil pada foto penuh; lisensinya ada di [panduan gambar](article-images.md).

Verifikasi: unit normalisasi/cursor, rules privasi dan indexed query, regresi 24 tes bot, 47 artikel emulator dengan timestamp sama, pencarian artikel di luar halaman pertama, filter gabungan, hasil kosong, sembilan hasil tepat, navigasi mundur/refresh, pembaruan indeks dari editor manual, sidebar, dan lebar 320–1440. Production build diuji ke Firebase online untuk pencarian prefix + topik, hasil kosong, daftar isi dan ukuran teks.

Inspeksi visual mempertahankan Barlow dan warna website. Pengecualian spesifik: judul lengkap artikel terbit boleh membungkus tiga baris pada HP; preview judul arsip dipotong dua baris secara visual sambil mempertahankan teks lengkap untuk aksesibilitas (pengukuran Range dapat tetap menghitung baris yang terpotong). Jumlah halaman dan tautan Baca tulisan adalah kontrol/data arsip, bukan label dekoratif. Komponen editorial ini tidak memerlukan video, empat foto baru, atau animasi pemasaran. Tidak ada foto atau font baru yang ditambahkan. Halaman kebijakan tetap ada dalam arsip, tetapi tidak dipromosikan sebagai rekomendasi bacaan berikutnya.
